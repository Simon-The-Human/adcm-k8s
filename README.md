# ADCM Kubernetes Platform Sandbox

Индустриальная песочница для локального развертывания **Arenadata Cluster
Manager (ADCM)** и **PostgreSQL 16** в кластере Kubernetes (`minikube`) с
использованием декларативного Nix-окружения, изолированной сетевой модели и
lifecycle-управления через Flake Apps.

## 🎯 Архитектурные принципы

1. **Воспроизводимая среда разработки:** Полная изоляция инструментария
   (`kubectl`, `minikube`, `helm`, `python`, `yq`, `jq`) через Nix Flakes и
   автоматическую активацию через `direnv`.
2. **Изоляция состояния (State Management):** Разделение базы данных и
   приложения с персистентным хранением данных через `PersistentVolumeClaim`
   (PVC) в выделенном пространстве имен (`adcm-sandbox`).
3. **Нативная сетевая модель (NodePort + Docker Bridge):** Отказ от локальных
   хаков (`/etc/hosts`, Ingress) в пользу прямой маршрутизации через сетевой
   мост Docker-драйвера Minikube.
4. **Lifecycle-автоматизация:** Управление стендом декларировано прямо во флейке
   через атомарные команды `nix run`.

## 🏗 Архитектура стенда

Компоненты развертываются в изолированном Kubernetes Namespace `adcm-sandbox`:

```
+--------------------------------------------------------------------------+
| Namespace: adcm-sandbox                                                  |
|                                                                          |
|  +---------------------------+       +--------------------------------+  |
|  | Deployment: postgres      |       | Deployment: adcm               |  |
|  |                           |       |                                |  |
|  |  [postgres:16]            |       |[hub.arenadata.io/adcm/...:2.12]|  |
|  |       |                   |       |       |                        |  |
|  +-------|-------------------+       +-------|------------------------+  |
|          |                                   |                           |
|    (PVC: postgres-data)                (PVC: adcm-data)                  |
+--------------------------------------------------------------------------+
          ^                                   ^
          | (ClusterIP)                       | (NodePort: 30080)
          +-----------------------------------+--------------------+
                                                               |
                                                       (Docker Bridge)
                                                       (Host Access IP)
```

* **PostgreSQL 16:** Обеспечивает персистентное хранение метаданных ADCM с
  проверкой здоровья через `livenessProbe` и `readinessProbe` (`pg_isready`).
* **ADCM (v2.12):** Основной управляющий сервис, подключенный к базе данных
  через внутренние переменные окружения Kubernetes.

## 📋 Системные требования

Для запуска песочницы на хост-системе требуется минимум внешних зависимостей:

1. **Docker Engine** — должен быть установлен и запущен в системе (используется
   Minikube в качестве драйвера контейнеризации).
2. **Nix** (с поддержкой Flakes) + **direnv** — для автоматической подготовки
   изолированного CLI-инструментария.

> **Примечание:** Все остальные инструменты (`kubectl`, `minikube`, `helm`,
> `k9s`, `python`) подтягиваются автоматически через Nix-окружение.
> Дополнительные настройки файрвола или ядра хоста не требуются.

## 🚀 Быстрый старт

### 1. Первичная настройка окружения (Bootstrap)

Если в системе еще не установлены Nix и `direnv`, вы можете запустить скрипт
автоматической установки:

```sh
bash scripts/setup.sh
```

*(Скрипт установит Nix через Determinate Systems, подключит `direnv` и создаст
файл `.envrc`).*

### 2. Активация окружения

При входе в директорию проекта окружение подхватится автоматически благодаря
`direnv`:

```sh
direnv allow
```

Либо активируйте его вручную:

```sh
nix develop
```

## ⚙️ Управление жизненным циклом (Lifecycle Apps)

Вся логика работы со стендом инкапсулирована в Nix Flake Apps. Никаких ручных
запусков и bash-скриптов — используйте стандартизированные команды:

* **Поднять стенд (проверить Minikube, включить драйвер, применить манифесты):**

  ```sh
  nix run
  ```

* **Проверить статус кластера и подов в неймспейсе:**

  ```sh
  nix run .#status
  ```

* **Полностью удалить ресурсы песочницы:**

  ```sh
  nix run .#down
  ```

После успешного запуска команда `nix run` автоматически вычислит актуальный
IP-адрес ноды Minikube в Docker-сети и выведет готовую ссылку для доступа к
веб-интерфейсу ADCM (например: `http://<MINIKUBE_IP>:30080`).
